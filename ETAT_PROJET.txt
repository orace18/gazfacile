3. DETTE TECHNIQUE CONNUE
================================================================================

  ── Haute priorité ──────────────────────────────────────────────────────────────

  [ ] Double système d'abonnement à unifier
      - Ancien : Revendeur.abonnement (GRATUIT, STANDARD, PREMIUM…)
      - Nouveau : Subscription + SubscriptionPlan (CLIENT_CONSULT, REVENDEUR…)
      - Fallback dans PaiementService.appliquerEffetsMetierPaiementApprouve()
      → Migrer les revendeurs vers le nouveau système, supprimer l'ancien

  [ ] CommandeDTO.clientTelephone encore validé @NotBlank mais ignoré par le service
      → Retirer le champ du DTO et du frontend

  ── Moyenne priorité ──────────────────────────────────────────────────────────────

  [ ] Pas de pagination sur les endpoints admin :
      - GET /api/v1/admin/utilisateurs → findAll() sans limite
      - GET /api/v1/admin/commandes    → findAll() sans limite
      → Ajouter Pageable (page, size) avec Spring Data

  [ ] ConsultationSession s'accumule sans nettoyage
      → Ajouter un @Scheduled qui supprime les sessions > 30 jours

  [ ] Auto-renouvellement non implémenté
      - Champ autoRenouvelle présent sur Subscription mais jamais traité
      → Implémenter dans AbonnementScheduler ou supprimer le champ

  [ ] Services inutilisés présents dans le code (dead code) :
      - GoogleAuthService (bouton Google retiré du login)
      - FirebasePhoneAuthService (flow retiré)
      → Supprimer si définitivement abandonnés

  ── Basse priorité ──────────────────────────────────────────────────────────────

  [ ] Pas de cache Redis
      - Chaque requête /revendeurs/nearby interroge MongoDB directement
      → Ajouter Redis pour les résultats géospatiaux (cache 5 min)

  [ ] LoginAttemptService en mémoire
      - Les compteurs brute-force se perdent au redémarrage
      - Ne fonctionne pas en multi-instance
      → Migrer vers Redis si passage à plusieurs instances

  [ ] Broker WebSocket in-memory
      - Ne scale pas en multi-instance
      → Migrer vers RabbitMQ ou Redis Pub/Sub si multi-instance

1. VUE D'ENSEMBLE DU PROJET
================================================================================

GazFacile est une plateforme de localisation de revendeurs de gaz domestique
au Bénin. Elle met en relation des clients cherchant du gaz avec des revendeurs
de proximité, avec gestion de commandes, paiement mobile money, abonnements et
notifications en temps réel.

Fonctionnalités principales :
  - Annuaire géolocalisé de revendeurs (carte + liste)
  - Quota freemium pour visiteurs anonymes (3 consultations gratuites)
  - Système d'abonnements pour clients (consultation, livraison)
  - Système d'abonnements pour revendeurs (STANDARD, PREMIUM)
  - Commandes de gaz avec paiement FedaPay (MTN, Moov, Celtiis)
  - OTP par SMS via CPass (identification sans mot de passe)
  - Notifications temps réel via WebSocket (STOMP/SockJS)
  - Dashboard admin complet (stats, utilisateurs, transactions)

Stack technique :
  Backend  : Spring Boot 3.3.0 / Java 21 / Maven
  Frontend : Angular 17/18 standalone components
  Base de données : MongoDB 7 (document store + index géospatial)
  Paiement : FedaPay (agrégateur MoMo Bénin)
  OTP SMS  : CPass (passerelle africaine)
  Auth     : JWT (jjwt 0.12.3) + Firebase Phone + Google OAuth
  Temps réel : STOMP over SockJS/WebSocket
  Infra    : Docker Compose (4 services)

2.3 SERVICES (LOGIQUE MÉTIER)
────────────────────────────────────────────────────────────────────────────────

AuthService
  - loginAvecOtp(telephone, code) : vérifie OTP → crée/charge user → JWT
  - register(dto) : vérifie OTP pré-vérifié → crée User + profil selon rôle
  - loginAvecGoogle(idToken, ...) : valide via GoogleTokenService → JWT
  - Génère access + refresh token via JwtService

RevendeurService
  - CRUD complet avec validation propriétaire
  - rechercherProches(lat, lng, rayon) : requête MongoDB $nearSphere
  - Met à jour stockStatus et notifie les abonnés WebSocket

CommandeService
  - creerCommande() : valide disponibilité stock → crée commande → envoie notif revendeur
  - mettreAJourStatut() : transitions d'état (PENDING → CONFIRMED → DELIVERED/CANCELLED)
  - Notifie le client à chaque changement de statut

ConsultationService
  - verifierEtIncrementer(fingerprint, ip) : gère le quota freemium anonyme
    * Cherche session par fingerprint, crée si absente
    * Vérifie via ipAtteintLimite() si une AUTRE session sur le même IP a atteint la limite
    * Incrémente le compteur si autorisé
  - consulterAuth(userId) : vérifie quota abonnement utilisateur connecté
  - ipAtteintLimite(ip, fingerprintExclu) : stream sur toutes les sessions de l'IP,
    anyMatch sur sessions n'appartenant pas au fingerprint courant ET >= LIMITE_GRATUITE (3)

OtpFacade
  - RATE_LIMIT_SECONDS = 60L (constante publique)
  - initOtp(telephone) :
    1. Normalise le numéro (format local)
    2. Vérifie existsByPhoneNumberAndUsedFalseAndCreatedAtAfter(phone, now-60s)
    3. Lance RateLimitOtpException si OTP récent non utilisé trouvé
    4. Normalise au format international (+229...)
    5. Appelle CPassOtpService.sendOtp()
    6. Persiste CpassOtpRef en base
    7. Retourne le referenceId CPass
  - verifyOtp(telephone, referenceId, code) :
    1. Cherche CpassOtpRef par referenceId
    2. Appelle CPassOtpService.verifyOtp()
    3. Marque la référence used=true

CPassOtpService
  - Intègre l'API CPass : POST /otp/send, POST /otp/verify
  - Authentification via CPassTokenService (Bearer token, TTL géré)
  - Paramètres : baseUrl, enabled (désactivé → simulation locale)

PaiementService
  - initierPaiement(dto) : crée transaction FedaPay → persiste Transaction PENDING
  - traiterWebhook(fedaPayId, statut) : met à jour statut + effets métier
  - appliquerEffetsMetierPaiementApprouve(transaction) :
    * COMMANDE → marque commande PAYÉE
    * ABONNEMENT + subscriptionId → subscriptionService.activateSubscription()
    * ABONNEMENT + revendeurId (fallback) → abonnementService.activerAbonnement()
  - appliquerStatut() : idempotent (ignore si ancienStatut == nouveauStatut)
  - synchroniserTransactionSiNecessaire() : re-interroge FedaPay si PENDING

SubscriptionService
  - getPlans(type) : retourne plans filtrés par type (CLIENT_CONSULT, CLIENT_LIVRAISON)
  - subscribe(userId, planId) : crée Subscription PENDING → initie paiement FedaPay
  - activateSubscription(subscriptionId, transactionId) :
    * Vérifie statut != PENDING → ignore (idempotence)
    * Passe à ACTIVE, calcule dateFin (dateDebut + plan.dureeJours)
  - checkExpiredSubscriptions() : expire les subscriptions dont dateFin < now

AbonnementService
  - activerAbonnement(revendeurId, montant) : calcule durée selon montant → ACTIVE
  - expirer les abonnements revendeurs expirés (AbonnementScheduler)

FedaPayService
  - creerTransaction() : POST /v1/transactions
  - obtenirToken(id) : GET /v1/transactions/{id}/token
  - construireCheckoutUrl(token) : "https://checkout.fedapay.com/{token}"
  - recupererStatutTransaction(id) : GET /v1/transactions/{id}
  - Signature webhook : HMAC-SHA256 sur le corps de la requête

PhoneNumberService
  - normaliserTelephoneLocal(tel) : retire +229 / 00229, retourne format 10 chiffres
  - normaliserTelephoneInternational(tel) : ajoute +229 si absent

2.5 MODÈLES & ENTITÉS

User (@Document "users")
  String id, telephone (unique), email, passwordHash
  List<Role> roles
  AccountStatus status (ACTIVE, SUSPENDED)
  LocalDateTime createdAt

Revendeur (@Document "revendeurs")
  String id, userId (ref User), nom, quartier, adresse, ville
  GeoJsonPoint location  [index 2dsphere]
  String telephone
  Abonnement abonnement (GRATUIT, STANDARD, PREMIUM)
  StockStatus stockStatus
  List<ProduitRevendeur> produits (embedded)
  boolean livraison
  double noteMoyenne, int nombreAvis

Commande (@Document "commandes")
  String id, clientId, revendeurId
  List<LigneCommande> lignes
  double montant
  StatutCommande statut
  StatutPaiement statutPaiement
  String referenceTransaction
  String adresseLivraison
  LocalDateTime createdAt

ConsultationSession (@Document "consultation_sessions")
  String id, fingerprint (UUID localStorage), ipAddress
  int nombreConsultations
  static final int LIMITE_GRATUITE = 3
  LocalDateTime premiereConsultation, derniereConsultation

CpassOtpRef (@Document "cpass_otp_refs")
  String id, phoneNumber, referenceId
  boolean used
  Instant createdAt  [TTL index : expire après 10 minutes]

Transaction (@Document "transactions")
  String id, fedaPayId (Long), reference, montant
  TypeTransaction type (COMMANDE, ABONNEMENT)
  StatutFedaPay statut (PENDING, APPROVED, DECLINED, CANCELLED, REFUNDED, TRANSFERRED)
  String commandeId, revendeurId, subscriptionId
  String checkoutUrl, token
  LocalDateTime createdAt, updatedAt

Subscription (@Document "subscriptions")
  String id, userId, planId, transactionId
  SubscriptionStatus statut (PENDING, ACTIVE, EXPIRED, CANCELLED)
  LocalDateTime dateDebut, dateFin
  boolean autoRenouvelle

SubscriptionPlan (@Document "subscription_plans")
  String id, code (ex: "CLIENT_CONSULT_BASIC"), nom
  String planType (CLIENT_CONSULT, CLIENT_LIVRAISON, REVENDEUR_STANDARD, REVENDEUR_PREMIUM)
  double prix
  int dureeJours, quota
  List<String> features
  boolean recommande

7. BUGS CORRIGÉS (SESSIONS PRÉCÉDENTES)
================================================================================

BUG #1 — Vérification IP incomplète (ConsultationService)
  Fichier : ConsultationRepository.java + ConsultationService.java
  Problème : ipAtteintLimite() utilisait findFirstByIpAddress → ne vérifiait
             que la première session, pas toutes les sessions de l'IP.
             Un fraudeur pouvait contourner en changeant de fingerprint.
  Fix : Ajout de findAllByIpAddress() + stream().anyMatch() excluant le
        fingerprint courant.

BUG #2 — Utilisateurs connectés bypassaient le quota (RevendeurCardComponent)
  Fichier : revendeur-card/revendeur-card.component.ts
  Problème : onCommander() avait un early return pour les connectés, skippant
             consultationService.consulter(). Les abonnements épuisés n'étaient
             jamais détectés.
  Fix : Suppression du early return → tous les utilisateurs passent par
        consulter(). Le paywall s'adapte selon data.estConnecte.

BUG #3 — Pas de rate limiting sur l'envoi d'OTP (OtpFacade)
  Fichiers : OtpFacade.java, CpassOtpRefRepository.java,
             RateLimitOtpException.java, GlobalExceptionHandler.java
  Problème : Aucun délai entre deux envois d'OTP → spammable, coûts CPass.
  Fix : Constante RATE_LIMIT_SECONDS = 60L + vérification
        existsByPhoneNumberAndUsedFalseAndCreatedAtAfter() avant sendOtp().
        HTTP 429 en réponse via GlobalExceptionHandler.

BUG #4 — Webhook FedaPay idempotence (PaiementService)
  Fichier : PaiementService.java
  Problème : Signalé comme bug, mais appliquerStatut() avait déjà le guard
             ancienStatut == nouveauStatut → return. Déjà correct.
  Action : Ajout d'un log.debug explicite pour traçabilité.

BUG #5 — Carte ne centrait pas sur le revendeur (MapComponent)
  Fichier : map.component.ts
  Problème : focusRevendeur() utilisait un champ mapInstance jamais assigné.
  Fix : @ViewChild(GoogleMap) googleMapRef + utilisation de
        googleMapRef.googleMap (instance native) pour panTo() et setZoom().

8. POINTS D'ATTENTION / LIMITATIONS CONNUES
================================================================================

SÉCURITÉ
  - SetupController (/setup/seed) doit être désactivé ou protégé en production.
  - La valeur JWT_SECRET doit être longue (>= 256 bits) et stockée dans un vault.
  - FIREBASE_SERVICE_ACCOUNT_JSON et FEDAPAY_API_KEY ne doivent jamais être
    committés — ils doivent passer exclusivement par les variables d'environnement.
  - Les imports GoogleAuthService et FirebasePhoneAuthService restent dans le
    codebase même si le bouton Google est retiré de login.component.ts. Si ces
    features sont définitivement abandonnées, les services peuvent être supprimés.

TESTS
  - Couverture très faible (3 fichiers). Aucun test de contrôleur, aucun test
    d'intégration MongoDB. Priorité : AuthController, PaiementController (webhook).
  - Pas de tests frontend Angular (Jasmine/Jest).

FREEMIUM
  - La limite LIMITE_GRATUITE = 3 est une constante Java compilée. Pour la rendre
    configurable, la déplacer dans application.yml.
  - Le fingerprint (UUID localStorage) peut être effacé → un même utilisateur
    peut contourner la limite en mode navigation privée sur une nouvelle IP.

PERFORMANCES
  - Pas de cache Redis → chaque requête /revendeurs/nearby interroge MongoDB.
  - Pas de pagination sur /api/v1/admin/users ni /api/v1/admin/commandes.
  - Polling des notifications (toutes les X secondes) — le WebSocket STOMP est
    configuré mais l'intégration client peut ne pas être active partout.

ABONNEMENTS
  - Le double système Abonnement (ancien, sur Revendeur) et Subscription (nouveau)
    coexiste avec un fallback dans appliquerEffetsMetierPaiementApprouve(). Le
    système hérité doit être migré puis supprimé.
  - Auto-renouvellement non implémenté côté paiement (flag autoRenouvelle présent
    mais non traité dans les schedulers).

INTERNATIONALISATION
  - L'application est en français uniquement. Pas de i18n configurée.
